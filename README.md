# 藏知（Cangzhi）

藏知是一个以“低打扰、自动沉淀”为核心的个人知识库。第一阶段优先解决：快速采集、自动解析与分类、混合检索、带原文引用的问答，以及通过用户纠正逐步学习个人偏好。

## 当前状态

M2 已完成：除随手记和文件外，现已支持安全收藏公开网页、保存 HTML 快照并提取正文；系统自带 10 个一级分类，可自动摘要、分类和生成标签。未配置模型时资料仍会正常解析，并自动进入“待整理”。

M3 混合检索已上线：解析成功后 Worker 会自动生成结构优先的父子切片；当前启用向量档案存在时，搜索和问答会分别召回关键词与向量候选，再用 RRF 融合排序。分类、标签和来源过滤同时作用于两路；向量服务异常时自动退回关键词检索，页面会显示实际召回方式和降级原因。

M3-2/M3-6c 已交付带引用的单轮混合问答：`/ask` 页面接收自然语言问题，基于父子切片做关键词与向量混合召回，再调用 OpenAI-compatible 或 Ollama 生成结构化回答并强制引用证据；引用卡片可点回资料详情。模型未配置时给出友好占位，无证据时不会调用模型，回答必须基于提供的证据，伪造或缺失引用都会被拒绝。

M3-3 已交付单用户认证与网页模型设置：首次启动访问 `/setup` 创建唯一管理员，scrypt 哈希、12 小时 HttpOnly + SameSite=Lax 会话 Cookie；登录、退出、登录状态都通过 `/api/auth/*` 暴露。除健康检查和 `auth/*` 外，所有 `/api` 业务路由都通过 `require_admin` 依赖在服务端鉴权，没有任何环境变量可以绕过。`/settings` 页面可选用 OpenAI 兼容协议或 Ollama，密钥以 Fernet 加密落库（主密钥位于共享 `storage/.secret_key`，0o600 权限），页面只回显 `has_api_key` 布尔值，连接测试对响应做脱敏。`/ask` 在未配置模型时直接提示前往 `/settings`。Web 配置始终覆盖 `.env` 设置，Worker 在每个任务里重新读取数据库配置，无需重启。

M3-4 新增确定性文档类型检测：切片前自动检测文档类型（general/legal/contract/paper/meeting/code/table），不依赖 LLM 所以结果确定且快速；根据检测结果自动调整切片参数，code/table 使用更大块参数保持结构完整；检测结果和块统计写入版本元数据，每个切片也会记录类型信息。重复处理结果确定且幂等，已有文档需要显式 reprocess 后获得新策略。兼容 SQLite 和 PostgreSQL 两种数据库。

M3-5 完善模型配置：OpenAI-compatible 和 Ollama 均可从已保存的服务查询模型列表，在设置页快速选择或刷新；不提供列表的服务仍可手动输入。首次配置可以先保存地址和密钥，再获取模型名称并保存。

M3-6a～M3-6c 已完成独立 Embedding 渠道、兼容性测试、版本化全库构建、失败重试、原子启用、一键回滚和混合检索。查询只使用当前 active profile；配置候选模型不会污染正在服务的索引。

分类整理支持自动补跑：保存可用的问答模型后，系统会自动重新整理“待整理/未分类”的已有资料；资料详情页也可以手动选择主分类并覆盖模型结果。

## 现在可以做什么

- 创建、查看和编辑随手记，每次实质修改保留新版本
- 上传 PDF、DOCX、Markdown、TXT，自动提取正文文本并保持文档结构
- 流式保存原文件并计算 SHA-256，相同内容复用一份 Blob
- 可靠后台异步处理，支持指数退避重试
- 浏览全部资料，详情页显示处理状态和错误信息，处理失败可手动重试
- 下载已保存的原文件和查看解析后的正文
- 粘贴公开网页链接，异步保存快照并提取标题、作者、发布日期和正文
- 使用默认分类树管理资料，也可以新增、改名或删除未使用分类
- 统一管理知识生命周期：资料先进入回收站，可恢复、批量永久删除或清空；共享原文仅在最后一个引用删除后清理
- WebDAV 连接器支持停用、影响预览和安全删除，远端始终只读；重连会按稳定文件身份去重，永久排除的文件不会自动复活
- 单篇知识可导出 Markdown/JSON，“设置 → 数据与备份”可下载可脱离系统阅读的全库 ZIP
- `scripts/backup.sh` 同时备份 PostgreSQL 与 storage，支持校验并在隔离临时数据库完成恢复演练
- 模型配置完成后自动分类新资料并补跑历史未分类资料；详情页可手动更改主分类
- 可选接入 OpenAI-compatible 或 Ollama，自动生成摘要、主分类和标签
- 未配置模型或模型暂时不可用时自动降级，不影响原文入库
- 解析完成后自动生成结构优先的父子切片，支持中文/英文/数字
- 用关键词与向量混合搜索资料；支持按分类、标签、来源类型过滤，结果含章节路径、定位信息和原文片段高亮
- 在 `/ask` 用自然语言提问，答案会引用资料中的具体片段，引用卡片可点回资料详情；未配置模型时给出友好提示
- 首次启动访问 `/setup` 创建唯一管理员账户；之后通过 `/login` 登录、顶部导航的“退出”按钮注销
- `/settings` 页面在网页上配置问答模型和可选 Embedding 模型，可查询模型列表、快速切换并分别测试连接；密钥以加密形式落库

下一步进入个人 Beta 稳定性和检索质量评测，并逐步加入多轮问答；邮件转入、浏览器插件、法律/合同深度解析和知识图谱安排在个人 Beta 之后。

## 设计原则

1. **默认自动完成**：高置信度结果直接落库，只有异常资料进入“待整理”。
2. **原文永不丢失**：所有摘要、切片和回答都可以追溯到原文件或网页快照。
3. **结构优先，AI 辅助**：优先依据标题、章节、段落、页码和条款切分，AI 处理结构不清和领域特殊内容。
4. **不是只有向量搜索**：默认采用全文搜索、向量搜索和元数据过滤的混合检索。
5. **配置渐进披露**：普通使用无需写提示词；模型、模板和切片规则放在高级设置中。
6. **可迁移、可重建**：原文和结构化元数据是事实源，索引与向量均可重建。

## 推荐首版技术栈

- Web：Next.js + TypeScript
- API：FastAPI + Python
- 数据库：PostgreSQL + pgvector
- 后台任务：数据库任务表 + 独立 Worker；规模扩大后再切 Redis 队列
- 文件存储：本地文件系统；后续兼容 S3/MinIO
- 文档解析：Docling 为主，格式专用解析器兜底
- 检索：PostgreSQL 全文搜索 + pgvector + RRF 融合 + 可选 Reranker
- 部署：Docker Compose，本机或个人服务器单命令启动

## 首次交付定义

当下面这条链路完整可用时，藏知即可开始投入个人使用：

> 粘贴一篇文章链接 → 自动下载和解析 → 自动归类 → 在知识库中找到 → 提问并得到带出处的回答 → 修改错误分类且系统记录纠正。

## 本地开发启动

### 前置要求

- Docker 和 Docker Compose
- Python 3.11+（本地开发时使用）
- Node.js 20+（本地前端开发时使用）

### 快速启动

1. 复制环境变量模板：

```bash
cp .env.example .env
```

2. 一键启动所有服务：

```bash
make up
```

这会启动：

- PostgreSQL 16 + pgvector
- 自动运行数据库迁移
- FastAPI 应用（http://localhost:8000）
- 后台处理 Worker
- Next.js Web 应用（http://localhost:3000）

打开 Web 后，如果还没有管理员账户会被引导到 `/setup` 创建；之后通过 `/login` 登录即可使用“记录一个想法”“上传资料”“收藏链接”“查看全部资料”。默认单个文件上限为 50 MB，网页快照上限为 5 MB。

AI 是可选项：不配置时系统仍可完整采集和解析，资料会进入“待整理”。如需自动摘要、分类和标签，先在 `.env` 中设置 `AI_PROVIDER=openai` 并填写 API 配置（适合只读环境），或者登录后在 `/settings` 页面配置。后者会立刻生效，覆盖 `.env` 设置；密钥只加密保存在服务器，页面只回显“是否已保存”。

### 常用命令

```bash
# 查看服务状态
make ps

# 查看日志
make logs             # 所有服务
make logs-api         # 仅 API

# 重新运行迁移（本地开发）
make migrate

# 运行测试
make test             # 所有测试
make test-api         # 仅 API 测试

# 停止服务
make down

# ⚠️ 停止服务并删除所有数据库数据（清空后无法恢复）
make down-volumes

# 完整安装所有依赖到本地（用于 IDE 提示和本地测试）
make install
```

### 健康检查端点

- Web：`GET http://localhost:3000/api/health`，返回 200 表示正常
- API liveness：`GET http://localhost:8000/api/liveness`，进程存活即返回 200
- API readiness：`GET http://localhost:8000/api/readiness`，数据库连接正常才返回 200

# ADR-034：跨进程模型调用准入（开发草案，禁止部署）

日期：2026-10-23。状态：设计与实现尚未完成验收。
分支：`codex/CZ-Q09-admission-recovery-draft`，负责人Codex（OpenCode协作）。
生产仍是v1.3.8/迁移0041；本草案的0042没有进入正式环境。

## 决策

- API和Worker通过PostgreSQL短事务共用模型额度，不能按空间、模型名称或Profile
  复制渠道额度。默认全部共用`model`池：总并发2、后台最多1、OCR子限额1。
  只有确定上游额度独立时，才通过用途到池的非敏感映射分开；该映射尚不等于完善的
  账号/渠道级配置管理，未接入管理页面或Compose环境变量透传。
- 外发前获取名额，网络请求不占用准入事务；唯一持有者令牌用于CAS释放。
  槽位TTL大于请求绝对硬期限，协调库失联时不允许新请求绕过准入。
- 真实传输采用可取消AsyncClient；同步Worker用asyncio.run运行完整异步调用。
  禁止用wait_for(to_thread(同步HTTP))冒充中止请求。取消获取时等待短数据库操作
  结束并清理；释放必须等待真实HTTP退出。
- 释放数据库失败保留租约至到期，不能丢弃成功结果而诱发付费重放。
  429冷却使用数据库时间，不因短冷却覆盖更长冷却；准入层不增加HTTP重试。
- 未发出请求的Busy/Unavailable/Cooldown应延后执行；实际发出后超时不能冒充未调用，
  不能自动退还增强调用预算。普通任务恢复由ADR035另行验收。

## 当前代码与验证

0042草案新增额度池及活动租约表。核心实现覆盖短事务、总量/后台/OCR限制、唯一
持有者、过期回收、有限等待、429冷却、请求总期限、取消清理及测试专用内存后端。

独立验证：准入单元/生命周期/冷导入23项通过；隔离PostgreSQL多进程容量、前后台
限制、CAS、锁超时、过期与冷却10项通过。包括真实本地HTTP慢速响应、取消关闭连接、
重复取消获取、释放失败不丢成功结果；不是生产模型质量或吞吐验收。

目前只开始接入对话Provider与后台向量，尚不代表所有调用经过此层。查询向量、
canary、模型测试、外部OCR、Busy穿过既有降级分支、增强预算及原有传输测试适配
尚未全部完成。不能将这些目标写成已实现，不能部署本分支作为正式版本。

## 发布阻断项

1. 完成所有真实调用点接线，包括设置页测试；GET模型列表不消费生成额度。
2. 底层辅助切片/增强的广义异常捕获不能吞掉Busy，Worker应延后而不是标整理失败。
3. 仅退还明确未发出的那一次增强预算；多窗口部分调用不能整体退款或无限重试。
4. 401/403/模型不存在的暂停与恢复、临时5xx冷却、运行指标与用户状态仍需实现。
5. 配置校验、Compose透传、既有API/Worker回归、迁移升级回退和发布检查必须完成。
6. 与ADR035共同验证后再评估v1.4.0；不提前打正式标签，不把核心测试当成整体完成。

## 边界

不改变REST/MCP知识范围契约、不读取或保存明文凭据。池ID必须是非敏感标识。
生产从未执行0042，当前无需回退。未来发布须保留旧镜像/联合备份并评估在途任务；
不得通过将容量设为极大值来伪装关闭限制。

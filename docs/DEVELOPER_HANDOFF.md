# 藏知开发交接

更新：2026-09-20。本文是可提交 Git 的通用交接，不是生产操作授权。

## 1. 产品目标

中文品牌：藏知；英文标识：Cangzhi；定位：个人可控的 AI 知识中枢。
品牌短句：藏有所知，问有所据。

目标是让资料可靠保存、自动整理、可追溯检索，并为外部 AI 提供自主探索路径。
AI 有两个位置：入库时辅助摘要/分类/标签及可选增强；使用时由内置或外部 Agent
自主规划探索。外部 MCP/Skill 的事实读取不应隐式调用藏知模型替外部 Agent 思考。
不追求通用 BI、完整 Excel 编辑器、多用户组织权限或全量知识图谱。

## 3. 下一目标：Excel 是二维知识载体

不能在“全转关系表”和“全拆文字向量”之间二选一。以逻辑区域而非整个 Sheet 分流：

| 区域 | 目标处理 |
|---|---|
| 标准二维明细 | 保持现有精确查询 |
| 多级表头/交叉报表 | 经校验生成查询视图，映射回原单元格 |
| 层级目录/分类清单 | 条目与父子关系，代码查找、完整注释、上下级枚举 |
| 标题/说明/备注 | 与相关区域或条目关联，不丢弃、不当成数据行 |
| 未可靠识别 | 保留二维事实并允许有界阅读，不冒充可靠统计表 |

所有新产物绑定文档版本与来源指纹，保留原始值、显示值、公式/缓存、合并范围及坐标。
关系型记录与单元格存储不同：保存到数据库不代表已经解释为业务明细。
AI 可以提出区域、表头、条目和父子关系；程序检查有效坐标、覆盖、冲突、重复归属及
预算。禁止补造数据、执行任意模型 SQL/代码、默默重算公式或访问工作簿外部链接。
代表样本用于提出解释，不能凭几个样本宣称全表均已验证。

### 三批交付

1. **CZ-X01：二维事实与区域阅读。** 先写 ADR（公共工具契约含分页、范围/版本约束、
   截断与预算），再实现版本化单元格/合并范围存储、区域目录与范围读取。先正确读取，
   不依赖 AI 成功；所有接口复用服务层，权限先于读取。大表分块/分页，不全表送入上下文。
2. **CZ-X02：受校验结构解释。** 规则产生候选区域，AI 针对有界结构/代表行及必要的
   局部阅读提出映射。确定性校验失败只降级该区域；预算、成本、覆盖、失败可见。
   标准表不强制新增模型调用。高级理解归入可选增强，不删除基础摘要分类标签。
3. **CZ-X03：探索与质量闭环。** 目录/范围/条目/上下级/已确认查询视图统一供网页、
   REST、MCP、CLI、Skill消费。向量用于发现，精确枚举/计算由结构执行。候选和现网
   对照验收后才切换；历史重建必须另获授权，新代未完成不能替换现有可用代。

Docling 可作结构解析对照、Unstructured 可借鉴区域拆分、SpreadsheetLLM 可借鉴
结构压缩。它们是评估候选，不是已选依赖或生产准确率承诺，不直接替换当前读取底座。

## 4. 完成标准与代码入口

完成不是“切片更少”或“向量跑完”，而是：标准表查询不退步、内容与定位不丢失、
复杂表问题可完整取证、无法判定时明确拒绝精确计算。建立跨类型至少30题的对照集，
记录正确条目/区域、完整性、枚举/聚合、来源定位、token、耗时、失败与降级。
不能为某个文件名、资料ID、行业关键词写特例。真实测试文件由维护者私下提供。

- 解析：`apps/api/parsers/spreadsheet.py`、`spreadsheet_layout.py`
- 结构化行/数据集：`apps/api/services/structured_table.py` 及数据集服务
- 切片/索引：`apps/api/services/chunker.py`、`apps/worker/services/processor.py`
- 原文导航/增强：`apps/api/services/source_navigation.py`、`knowledge_enhancement.py`
- 鉴权/范围：`docs/EXTERNAL_CLIENT_ACCESS.md`、ADR-021/022
- 测试入口与样例说明：[SPREADSHEET_TESTING.md](SPREADSHEET_TESTING.md)

## 5. 协作和信息分类

开工遵守 AGENTS 的必读顺序、一个任务一个分支、先登记负责人和目标。用户偏好
OpenCode CLI 会话方式编写代码，可考虑可用的 M3/ark；负责人仍需审阅、测试，不以
模型自述替代验收。不要读取 `.env` 或打印任何凭据。

进入 Git：通用目标/ADR/架构/任务状态、代码测试、合成样例或生成器、非敏感验收结果。
不进入 Git：生产资料原件、数据库/存储快照、模型密钥、令牌、实际实例地址、生产资料ID、
备份路径与操作名单。测试记录使用测试编号，映射和原件私下交付。既有历史日志若需
脱敏是单独审查任务，不在本轮改写历史或做破坏性清理。

默认只交付代码、测试、迁移和文档；不部署、不启动普通Worker、不扩大旧队列，旧轮次
部署授权不自动延续。不要把旧代码直接连接迁移后的生产数据库当作回滚方案。

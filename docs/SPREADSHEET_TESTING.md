# Excel 测试资料与跨环境验收

本文可提交 Git，不包含生产资料原件、真实资料ID或认证信息。

## 1. 自动测试代码在哪里

| 文件 | 覆盖范围 |
|---|---|
| `apps/api/tests/test_spreadsheet_sparse.py` | 样式范围虚高、声明范围虚低、绝对坐标、空表、公式缓存、合并元数据、行列/文本预算、资源关闭 |
| `apps/api/tests/test_spreadsheet_layout.py` | 规则表与备注共存、合并表头、并排表、汇总行、无表头内容、回退全文与数据集分流 |
| `apps/api/tests/test_parsers.py` | Excel/其他格式解析、空白、显示值及公式基本行为 |
| `apps/api/tests/test_structured_table.py` | 结构化行提取与数据集相关服务 |
| `apps/worker/tests/test_chunking.py` | 后台切片及紧凑数据集目录 |
| `apps/worker/tests/test_processor.py` | 后台生命周期、向量策略及混合原文不可采样遗漏 |

前两份是 Python 测试程序，不是可上传的 Excel 附件。它们使用 openpyxl 在内存
构造合成工作簿；不依赖本机生产库，也未提交真实工作簿到仓库。

安装测试依赖后，在没有生产 `.env`、没有生产存储挂载的独立 checkout/容器运行：

```bash
python -m pytest apps/api/tests/test_spreadsheet_sparse.py apps/api/tests/test_spreadsheet_layout.py -q
python -m pytest apps/api/tests apps/worker/tests -q
```

数据库/存储/模型配置必须指向隔离环境，不能把“测试使用 SQLite”当作可随意加载
生产配置的理由。上次代码发布基线为1445通过、2跳过；跳过项目不视为已验证。

## 2. 需要上传到另一环境的真实资料

由维护者从现有实例“下载原文”后私下传输，**不要使用导出 Markdown、摘要、切片或
重存后的 Excel 代替原件**：重存可能消除导致范围误判的样式信息。

| 测试编号 | 资料类型 | 用途 |
|---|---|---|
| E01 | 带样式膨胀的层级分类目录 XLSX | 复现旧超限；检查完整注释、代码、父子关系、上下级枚举 |
| E02 | 已有查询效果良好的标准二维表，如菜单/订单明细 | 保证筛选、计数、去重、求和、列投影不退步 |
| E03 | 合并多级表头、单位与备注的报表 | 表头映射、单位、注释归属；不能错误补值 |
| E04 | 同一工作表并排表格、混合说明和合计 | 区域独立性、汇总不重复计入明细 |
| D01 | 普通 PDF/Word 资料 | Excel 改造不能改变非Excel检索与引用路径 |

真实文件名与 E01/D01 的对应关系通过私下交接提供，不放入公开仓库。E02–E04 需要
维护者选取脱敏原件，或接手者生成合成附件，不能假称已有完整真实测试集。
在私下清单记录文件名、SHA-256、字节数、测试编号；不得记录密钥或访问令牌。
不同环境的文档、版本、数据集 ID 会变化，不复制生产ID作为测试断言。

## 3. 验收记录应区分三个层次

1. **可靠解析**：有效值和公式无漏读，原始坐标/合并范围保留；样式膨胀不误判，
   真正超预算有明确错误。解析完成不等于 AI 结构理解成功。
2. **实际检索**：首部/中部/尾部问题均能取到正确证据，并展示范围和版本；明确词命中
   只能算冒烟测试。对照标准表精确查询和不规则表完整条目、注释、父子关系。
3. **新方案效果**：至少30道跨类型问题，标注期望答案与单元格/条目证据，分别记录
   召回、完整性、枚举/聚合正确性、引用定位、延迟、模型消耗与失败/降级。新接口应覆盖
   工作空间/文档选择/探索凭证边界，空范围、过期版本、截断分页和越权拒绝。

当前保守回退版本应验证“不乱算、不丢原文”，不能要求它已完成尚未实现的层级查询；
把层级理解等结果记为待实现，而非将预期降低为“查到了几个关键词”。

## 4. 调试入口

`scripts/check-spreadsheet-parser.py DOCUMENT_ID` 是本地候选与已安装解析器的只读
比较工具：依赖正在运行的 Compose API，使用当前环境的资料ID，不触发任务或模型。
它不是上传器、不是独立公共API验收，也不替代实际问题对照。生产原件不得写进Git。

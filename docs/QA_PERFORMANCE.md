# 快速问答耗时观测与无损优化

快速问答仍执行混合检索、范围内数据集发现、有限计划纠错、精确计算和引用校验。
不能为提速减少证据、跳过单位核验、把数据库计算改成模型猜数，或自动升级深度分析。

## 当前优化

- 排名完成后先按既有证据条数上限选中锚点，再加载分类/标签和切片正文，
  不再加载不会被选用的召回候选。不改变排名、选中集合或预算。
- 选中切片的邻居上下文由逐条读取改为一次有界查询。同文档、同版本、同父片段、
  当前 child 和相邻序号条件不变；表格不扩展半行，碎片 PDF 恢复和证据预算不变。
  合成 16 锚点测试（生产证据条数上限）由 16 次邻居读取降至 1 次，
  与旧路径逐条比较内容一致。
- 数据集字段由每个目录一次读取改为目录集合一次读取，字段顺序、解释、样例和
  实际行查询不变。不缩减规划候选，也不增加跨请求缓存或复用旧答案。
- 页面显示已等待秒数及已有处理阶段。秒数是浏览器等待时间，不是完成百分比或
  预计剩余时间；完成、失败或退出等待视图后清理计时器。最终回答仍经校验后整体展示。

## 如何定位耗时

API 的 INFO 日志每次快速问答输出一条 `qa_timing`，包含 `status`、`total_ms`
和 `stages_ms`，失败和取消路径也收尾。不写问题、正文、文档/空间标识、模型地址、
密钥或异常正文，不新增数据库写入及后台采样任务。

| 阶段 | 含义 |
| --- | --- |
| lexical_recall | 关键词召回，包含必要的回退 |
| vector_recall | 查询向量与向量召回，含渠道等待 |
| evidence_context | 分类标签、切片及上下文组装 |
| retrieval | 上述检索整体耗时 |
| dataset_discovery | 范围内候选数据集发现 |
| dataset_catalog | 字段、样例与字面值发现 |
| dataset_planning_model | 初始规划及既有格式纠错的模型耗时合计 |
| dataset_execution | 精确执行及单位核验耗时合计 |
| dataset_refinement_model | 既有一次语义纠错的模型耗时 |
| dataset_plan_execute | 数据集规划与执行总耗时 |
| answer_generation | 最终模型回答，包含渠道等待 |

父阶段包含子阶段，不能把所有阶段相加。没有进入的阶段不输出。
同一阶段多次执行累计耗时；并发问答使用请求局部上下文，互不混入。
取消记为未完成（failed）；日志只表示服务端处理，不包含浏览器、代理或历史保存耗时。

## 验证与局限

使用隔离 SQLite/合成数据验证内容等价、查询次数、失败/取消和并发计时隔离，
并运行问答、数据集执行、单位口径、片段恢复及 v1 接口回归。没有使用真实资料发起
付费模型请求；查询次数下降不是端到端提速比例。部署后应比较同范围问题的多次
阶段耗时及 P50/P95，再决定是否需要向量生成优化、模型渠道调整或更细的准入计时。
本批不承诺模型响应时限，不更改模型配置、并发额度、超时及准确性规则。

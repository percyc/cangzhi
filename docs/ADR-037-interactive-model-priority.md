# ADR-037：交互请求优先与模型故障隔离

日期：2026-10-23。承接 ADR-034；实现和验收状态见 PROJECT_STATUS。

## 问题

网页、MCP、API 问答与后台整理共用供应商额度是必要的，但额度池不是故障范围。
一个后台模型的 5xx 不应导致其他对话模型、查询向量也停止服务。获取模型列表成功
也不等于该模型可以实际回答问题。

## 决策

- 保留统一跨进程总额度，不按入口、模型或空间复制容量。API 服务中的网页、REST、
  MCP 交互均按前台计入；普通 Worker 及其任务子进程按后台计入。
- 总容量大于 1 时，后台有效上限不得占满总量，至少预留 1 个前台名额。
  不抢占已外发请求；总容量为 1 时无法同时预留前台并执行后台，不承诺无等待。
- 将故障身份与额度身份分离：仅存用途、端点、模型、凭据组合的不透明指纹，
  不把地址、模型请求正文或密钥保存到协调表及日志。
- 429 缺少可信限流范围信息时仍保守冷却共享额度池，遵守有界 Retry-After。
  401/403 与 5xx 限定对应故障身份；超时和非法输出不扩散为全池冷却。
- 冷却结束后以有限租约控制单次恢复探测，成功后才恢复常规并发。
  迟到成功不得清除更新的故障状态，探测取消或进程中断也不能永久占用名额。
- 不在传输层自动重放付费请求；后台沿用既有退避和未外发预算返还逻辑。
  等待、冷却、模型失败与无知识证据是不同状态，不能相互冒充。

## 边界与验收

优先级不能绕过真实的供应商全渠道限流，不能保证模型输出正确，也不改变检索排名、
知识范围或引用契约。必须测试总量、后台预留、故障隔离、429、跨进程探测、取消、
迟到成功和租约释放。真实问题单独验证，不用模拟响应或 HTTP 200 冒充答案正确。

协调状态升级需要所有外发进程同步使用新实现；旧版本产生的冷却不自动清空。
本批不自动部署、不重跑历史失败任务，也不改动事实源或线上索引。

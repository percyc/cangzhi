# ADR-022：短期 MCP 探索凭证

**状态**：已接受并实现 · **关联说明**：[外部系统接入](EXTERNAL_CLIENT_ACCESS.md)

## 背景

ADR-021 将 Scope Key 定义为文档分组而不是权限。普通 PAT 持有者因此可以在整个绑定
工作空间内探索，这适合可信集成。但第三方系统可能只允许某个用户选择部分知识，再把
MCP 交给外部 AI 自主调用。MCP 工具参数由模型生成，不能依赖模型每次都正确带上
`document_selection`，也不能把工作空间 PAT 暴露给客户端。

## 决策

1. 保留普通 `cz_pat_...` 直接调用 `/api/mcp` 的原有模式和工作空间级能力。
2. 绑定工作空间的 PAT 可通过 REST 创建短期、不透明的 `cz_eg_...` 探索凭证；创建时
   必须提供非空 `document_selection`，最长有效 24 小时。
3. 探索凭证只允许访问 `/api/mcp`，不允许调用 REST v1。它继承创建 PAT 的知识读取、
   搜索和问答作用域，不继承写权限。
4. 创建时的选择成为服务端不可扩大的硬边界。工具参数中的 KnowledgeScope、分类、标签、
   来源、连接器和 `document_selection` 只能继续与边界取交集。
5. 边界覆盖搜索、快速问答、数据集发现和查询，以及文档、切片、数据集和证据的按 ID
   读取；范围外对象统一按不存在处理。
6. 服务端只保存令牌 SHA-256、显示前缀、选择器和审计时间。明文只在创建响应出现一次，
   不提供列表或再次查看接口。
7. 凭证到期、被主动撤销、创建 PAT 被撤销/删除或管理员失效时立即不可用。Scope Key
   绑定按每次请求实时解析，因此第三方系统移除文档关联后无需重新签发即可收紧范围。

## 非目标

- 不引入用户、角色、拒绝规则或通用 ACL。
- 不把 Scope Key 本身变成秘密或认证凭证。
- 不建立有状态 MCP 会话；每个 HTTP 请求仍通过 Bearer 凭证独立认证。

## 安全性质

```text
effective documents = grant boundary
                    AND per-call document selection
                    AND knowledge scope / metadata filters
```

边界和调用筛选分别下推为 SQL 条件，不能用“指定文档 ID”“读取相邻切片”“数据集查询”或
“证据预览”绕过。探索凭证响应不返回固定边界中的 Scope Key 值，避免把第三方业务标识
暴露给外部 AI。

## 重新评估条件

若未来允许终端用户自行管理藏知账户、长期持有局部权限，或需要组织继承、拒绝规则与
资源共享，应建设正式的 workspace membership/ACL，而不是延长探索凭证生命周期。

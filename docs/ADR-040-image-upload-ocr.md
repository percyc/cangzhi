# ADR-040：独立图片上传与有界 OCR 方向纠正

日期：2026-10-29。维护者提出支持图片上传及修复横向 OCR，本决策限定为文字识别。

## 决策

- 共用上传校验开放 PNG、JPEG（jpg/jpeg）、静态 WebP；网页、REST、WebDAV
  使用同一白名单，不接受 SVG、动图或任意 image/*。通用二进制声明规范化为图片 MIME，
  后台再核验真实解码格式；上传成功不等于解析成功，原件始终保留。
- 使用现有 PDF OCR 管线处理单页图片：内存中的单页 PDF 仅用于复用页面调度，
  OCR 直接读取经 EXIF 纠正、透明底转白的无损图片，不对图片做 JPEG 二次识别。
  保持外部 OCR 触发条件、单文档预算、质量隔离及后续摘要/分类/切片流程。
- 结构类型增加 image。坐标属于 EXIF 校正后的图像，左下角原点，每单位一像素，
  页码固定为 1；旋转识别后回映此坐标系。详情页提供原图和解析正文核对。
- 限制图片为单帧、最多 2500 万像素、单边最多 12000 像素，拒绝损坏或超限输入，
  不将无可用文字的图片作为成功文档入库。限制是解码安全边界，不替代上传字节限制。
- 横版不等于方向错误：默认自动分区识别；低质量时尝试单文本块和旋转，
  各旋转公平分配剩余预算，不无限重试、不为方向探索额外调用外部模型。
- 不新增权限，不改变 scope、原件版本与引用校验；不实现图片语义描述，不将模型
  猜测当事实，也不在本次扩展 Word 混排图片提取。

## 局限

小字、模糊、复杂图表、竖排和同一图片多方向混排仍可能需要人工整理；
EXIF 校正坐标不是未经校正的原始像素坐标。无文字图片不自动生成语义描述。
现有文档不会后台重跑；管理员可按需重新处理。

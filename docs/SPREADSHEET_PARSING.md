# Excel 解析：有效范围与不规则结构

Excel 是文件格式，不保证内容是可计算的关系型明细。原始工作簿始终保留；解析结果、
数据集和检索切片是派生物。系统保存所有受支持 Excel，但知识消费只接受通过校验的
数据集区域；不能验证的复杂区域进入待治理状态。本策略不执行公式、不自动重跑历史文件。

## 有效范围

XLSX 先流式扫描工作表 XML 的值和公式位置，不能仅相信 dimension 或样式范围。
纯格式空白不扩大读取矩形；真正的数据即使在声明范围之外也不能漏掉。原始行号、
前导和中间空列保留，空行仍用于划分区域。合并范围记录为结构，不进行向下填充。
仍保留 250 MiB 解压大小、每表 15 万行、整簿 200 万展开单元格预算，新增整簿
3200 万格式化文本字符和每表 1 万合并范围上限，不能无限放开稀疏大坐标文件。
展开预算包含有效范围内的空位及前导空位，不等同于非空单元格数；真正跨度过大的
稀疏表仍会明确失败，而非构造无界矩形。本批有效范围修复针对 XLSX，旧 XLS 仍沿用
xlrd 的行列读取预算；两种格式共用布局风险回退。

## 数据集与治理两条路径

- 有可识别表头、未检测到结构风险的区域：沿用数据集目录及精确查询。
- 合并单元格、贯穿区域的中间空列、混排单值行、汇总行或未确认表头：整个区域
  标记 `dataset_eligible=false` 及 `layout_risks`，保留所有行、绝对列标签和原文件，
  但不生成普通文档切片、向量或可聚合明细。页面显示待治理及风险，避免错误统计，
  也避免将二维语义丢失后的长文本冒充可理解知识。
- 同一工作簿允许同时存在规则数据集区域和待治理区域。数据集目录仍可发现和精确查询，
  待治理区域不会混入检索结果。摘要、分类、标签仍按基础整理流程生成。

这是保守风险识别，不是完整的版面理解：合并表头暂不自动拆解，带独立标题的连续表
可能整体进入待治理，未显式标记的汇总、复杂透视和不规则层级仍可能无法识别。
不能把“没有检测到风险”理解为业务统计口径已经验证；数据集查询仍需核对表头与数据。
本批不调用 AI 猜测字段或补值。后续 AI 只面向标题行、第二行表头、常见合并表头等
通用形态提议区域/表头映射，经原坐标、覆盖、字段唯一性和行一致性校验后才激活。
复杂层级目录、透视报表和多口径混排应要求用户先治理，不能直接用模型生成的二维表
替代原文，也不为单个文件编写专用兼容。

## 验证与上线边界

回归覆盖格式虚高、声明范围虚低、内部空行/列、合并表头、说明混排、并排表、汇总行、
公式及真实资源上限。`scripts/check-spreadsheet-parser.py DOCUMENT_ID` 在现有 API
容器的独立进程中只读比较安装版与本地候选，不修改文件、资料状态或任务，不调用模型。

部署需由维护者执行。历史资料继续使用已有解析与索引，更新 Worker 后仍需明确发起
目标文档重解析才能修复历史失败；本次代码交付不自动恢复其他失败队列。

# ADR-026：Excel 采用“数据集或待治理”边界

- 状态：Accepted
- 日期：2026-09-20

## 背景

Excel 是容器格式，不保证其中内容是稳定的关系型明细。藏知已经具备标准二维表的
Parquet/DuckDB 精确查询，也能识别合并单元格、并排区域、说明/汇总混排和未确认表头
等风险。曾有实现将风险区域按普通文档全文切片并全量向量化；这虽然保留了文字，却
丢失二维语义、扩大存储和计算，并可能让用户误以为系统已经理解层级与统计口径。

## 决定

1. 所有受支持 Excel 仍可上传、版本化和下载。原文件与文档版本是事实源。
2. 只有通过确定性结构校验的区域生成 `KnowledgeDataset`、紧凑数据集目录及向量，
   精确筛选和聚合继续由 Parquet/DuckDB 执行。
3. `dataset_eligible=false` 的区域保留解析坐标、合并关系、标题、备注和风险诊断，但
   不生成普通全文切片或向量。页面显示“待治理”，提示用户整理后上传新版本。
4. 同一工作簿可以包含可查询数据集与待治理区域；前者正常服务，后者不混入检索。
5. 标题行、第二行表头、常见合并多级表头等通用形态可以逐步增加映射。AI 只能提出
   有界结构候选，程序必须校验坐标、覆盖、字段唯一性、冲突和明细一致性后才能激活。
6. 复杂层级目录、透视报表、多口径混排等无法通用验证的形态要求用户先做数据治理；
   不为单个文件名、资料 ID 或行业内容编写专用兼容。
7. 基础摘要、分类和标签继续保留；本决定只约束 Excel 的检索和数据集派生产物。
8. 策略更新不自动清理历史派生物。重建必须由维护者明确指定目标并在操作前备份，
   不改写原文件、文档版本或人工组织信息。

## 结果

- 标准二维表保持可发现、可精确查询，向量只承担数据集发现。
- 复杂工作簿不会因“全文可搜”而被误报为已结构化，也不会制造大量低价值向量。
- 用户需要在复杂文件上承担明确的数据治理步骤；藏知不承诺通用 Excel/BI 自动理解。
- 页面和处理状态必须区分“处理失败”与“解析完成但需要治理”。

## 重新评估条件

只有在跨行业真实样例证明某类布局具有稳定、可概括的验证规则，并通过标准表不退步、
拒绝误算、引用定位和成本评测后，才将该布局从待治理提升为自动数据集映射。

# ADR-033：指标级运行统计与真实采集时间

日期：2026-10-23。状态：已实现，部署状态见 PROJECT_STATUS。

## 背景

原知识规模快照有九条聚合，任一超时会使本组首次统计全部不可用。
界面仅根据成功时间判断是否执行过，不能区分未尝试和尝试失败。
统计仍须低负载，不能通过刷新网页触发全库查询或放宽数据库超时。

## 决定

- 0041 新增 `monitoring_metrics`，按 `(kind, metric)` 保存值、成功/尝试时间、
  安全错误类别、连续失败次数和下一次尝试时间。保持三组快照 `data` 兼容字段。
- 升级仅映射原快照已有值及原时间；失败不会清空旧值，从未成功保持未知。
  降级只删除指标派生表，不修改原快照和任何文档事实源。
- 单 SQL 探针一个保存点；同一 SQL 产生的多个计数共用该次成败，其他探针继续。
  健康指标正常周期不变，失败指标在 60–3600 秒内指数退避并错峰。
- 每组事务咨询锁与持久到期时间共同去重；SQL 上限 2500ms，锁等待 200ms，
  后续查询按剩余轮次预算收紧。统计只读元数据，不读取正文和向量数组。
- 容量趋势按实际 Blob 成功观测所属小时更新。同小时更新赋新 JSON 对象，
  不把旧观测挪到新小时；其他趋势字段只采用同一小时的观测或保持该小时已有值。
- 管理员页面只读最多三组快照、一百条指标及有界小时趋势，不增加外部令牌权限。
  各指标单独显示成功/尝试时间；首次失败、部分可用和过期不再混用“首次等待”。

## 边界

这是低频观察，不是事务一致的资产总账，也不能用采集线程心跳证明任务执行健康。
SQL 超时不是进程级硬终止；底层存储 `statvfs` 或数据库连接建立仍受各自基础设施约束。
本次不实现任务租约或模型并发治理，也不自动重试历史失败文档。

验收覆盖：保存点隔离、旧值/时间保留、退避、轮次预算、实际 PostgreSQL 超时恢复、
五万条向量计数、带旧 JSON 快照的迁移回退、浏览器首次失败/部分可用/恢复和手机布局。

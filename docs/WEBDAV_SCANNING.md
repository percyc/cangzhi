# WebDAV 后台扫描

本页描述需要迁移 `0039` 的后台扫描版本；实际部署状态见 PROJECT_STATUS。

## 使用方式

1. 在设置 → 知识源 → 文件来源配置并测试连接。
2. 点击“扫描文件”：立即提交后台任务，可以离开页面，返回后恢复服务端进度。
3. 页面显示已扫/待扫目录、发现文件与耗时；目录总数动态增加，不显示估算百分比。
4. 完成后点击“同步入库”，才下载新增/变化文件并进入解析流程。扫描本身不调用 AI。

扫描中可取消；失败或取消后可“从断点继续”，也可点击“扫描文件”重新开始。
继续保留已完成目录，仅重试未提交的目录；重新开始丢弃暂存扫描记录，不删除已入库资料。
来源配置变化后必须重新开始。扫描进行中需先取消，才可编辑、停用、删除来源或同步入库。

## 数据安全

- 所有目录完成后才一次性更新清单；中断不会把部分清单当成全量结果。
- 取消会立即使在途结果失效；远端请求可能仍在结束过程中，但不会写回该任务。
- 手动继续、进程重启后的租约恢复、持续超过24小时的扫描不累计远端缺失。
  这些结果仍可发现和更新文件；需要核对删除时进行一次重新开始且完整成功的扫描。
- 原有缺失确认仍需成功扫描次数与24小时保护期，且只在当前有效范围内判定。
- WebDAV没有整棵目录的事务快照；远端扫描期间移动文件仍可能产生时间差，不能承诺瞬时一致。

## 运维与限制

迁移0039只新增扫描状态与暂存文件元数据表，不重处理资料、不自动创建扫描任务。
升级应先备份，执行迁移，再更新API、Web和Worker。独立扫描循环位于普通Worker中，
不会等待一篇长文档解析结束；只运行历史专用维护脚本不具备该扫描循环。
长期“等待后台扫描”请检查Worker是否运行、数据库是否已迁移。
回退旧应用前应取消活动扫描，不要让新旧Worker同时执行来源操作；回退迁移会删除
扫描断点与暂存元数据，不删除已入库资料，操作前仍需备份。

每批最多3个目录请求，复用HTTP连接；每请求批次有30秒超时，120秒租约到期可恢复。
仍限制2000目录、10万返回条目、单目录16 MiB，超限请缩小来源目录；没有整树45秒限制。
每个来源仅保存当前任务，重新开始替换旧暂存。暂存仅保存路径与ETag等元数据，不保存凭据
或文件内容；失败暂存保留供继续，完成后清理。定时扫描、自动退避重试、全量运行历史、
后台下载/入库进度不在本批。

## 浏览器管理接口

均要求管理员登录和当前工作空间；不新增公共v1或MCP工具。

| 接口 | 行为 |
| --- | --- |
| POST `/api/webdav/{id}/scan-jobs` | 202，创建任务；已有活动任务则返回同一任务 |
| GET `/api/webdav/{id}/scan-jobs` | 当前任务与进度，未扫描过返回null |
| POST `/api/webdav/{id}/scan-jobs?resume=true` | 202，从失败/取消的断点继续；配置变化409 |
| POST `/api/webdav/{id}/scan-jobs/cancel` | 取消，保留断点，重复取消幂等 |
| GET `/api/webdav` | 每个来源的scan字段包含当前进度 |

旧POST `/scan`保留同步兼容模式（原45秒限制）；网页不再调用，不推荐新客户端使用。
扫描和同步入库互斥；状态与回收规则由同一服务层执行。

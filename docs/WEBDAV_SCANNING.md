# WebDAV 后台扫描

本页描述需要迁移 `0039` 的后台扫描版本；实际部署状态见 PROJECT_STATUS。

## 使用方式

1. 在设置 → 知识源 → 文件来源配置并测试连接。
2. 点击“扫描文件”：立即提交后台任务，可以离开页面，返回后恢复服务端进度。
3. 页面显示已扫/待扫目录、发现文件与耗时；目录总数动态增加，不显示估算百分比。
4. 完成后点击“同步入库”，才下载新增/变化文件并进入解析流程。扫描本身不调用 AI。

扫描中可取消；失败或取消后可“从断点继续”，也可点击“扫描文件”重新开始。
继续保留已完成目录，仅重试未提交的目录；重新开始丢弃暂存扫描记录，不删除已入库资料。
来源配置变化后必须重新开始。扫描进行中需先取消，才可编辑、停用、删除来源或同步入库。

## 数据安全

- 所有目录完成后才一次性更新清单；中断不会把部分清单当成全量结果。
- 取消会立即使在途结果失效；远端请求可能仍在结束过程中，但不会写回该任务。
- 手动继续、进程重启后的租约恢复、持续超过24小时的扫描不累计远端缺失。
  这些结果仍可发现和更新文件；需要核对删除时进行一次重新开始且完整成功的扫描。
- 原有缺失确认仍需成功扫描次数与24小时保护期，且只在当前有效范围内判定。
- WebDAV没有整棵目录的事务快照；远端扫描期间移动文件仍可能产生时间差，不能承诺瞬时一致。

## 运维与限制

迁移0039只新增扫描状态与暂存文件元数据表，不重处理资料、不自动创建扫描任务。
升级应先备份，执行迁移，再更新API、Web和Worker。独立扫描循环位于普通Worker中，
不会等待一篇长文档解析结束；只运行历史专用维护脚本不具备该扫描循环。
长期“等待后台扫描”请检查Worker是否运行、数据库是否已迁移。
回退旧应用前应取消活动扫描，不要让新旧Worker同时执行来源操作；回退迁移会删除
扫描断点与暂存元数据，不删除已入库资料，操作前仍需备份。

每批最多3个目录请求，复用HTTP连接；每请求批次有30秒超时，120秒租约到期可恢复。
仍限制2000目录、10万返回条目、单目录16 MiB，超限请缩小来源目录；没有整树45秒限制。
每个来源仅保存当前任务，重新开始替换旧暂存。暂存仅保存路径与ETag等元数据，不保存凭据
或文件内容；失败暂存保留供继续，完成后清理。定时扫描、自动退避重试、全量运行历史、
后台下载/入库进度不在本批。

## 浏览器管理接口

均要求管理员登录和当前工作空间；不新增公共v1或MCP工具。

| 接口 | 行为 |
| --- | --- |
| POST `/api/webdav/{id}/scan-jobs` | 202，创建任务；已有活动任务则返回同一任务 |
| GET `/api/webdav/{id}/scan-jobs` | 当前任务与进度，未扫描过返回null |
| POST `/api/webdav/{id}/scan-jobs?resume=true` | 202，从失败/取消的断点继续；配置变化409 |
| POST `/api/webdav/{id}/scan-jobs/cancel` | 取消，保留断点，重复取消幂等 |
| GET `/api/webdav` | 每个来源的scan字段包含当前进度 |

旧POST `/scan`保留同步兼容模式（原45秒限制）；网页不再调用，不推荐新客户端使用。
扫描和同步入库互斥；状态与回收规则由同一服务层执行。

## 目录浏览与选择导入（后续开发批次，发布以 PROJECT_STATUS 为准）

文件清单按最后一次完整扫描结果生成目录导航，分页在服务端完成，默认每页25项。
文件名、所在目录、入库状态和单文件失败原因分别呈现；支持目录下钻、返回上级、
路径文字搜索和状态筛选，不再一次展开全部文件。目录由已知文件推导，不代表远端
所有空文件夹，也不会在浏览时额外访问网盘。

导入范围可以是勾选文件、当前目录及子目录，或当前目录及子目录内的失败文件。
“当前目录导入”包括子目录，不受界面搜索词和状态筛选影响，操作前需明确确认；
选择为空不能解释为全量导入。跨页选择有数量上限，改变目录或筛选清空选择。
这些是本次操作范围，不是长期自动同步规则；取消勾选不删除已入库资料，不累计远端缺失。
长期关注目录可继续通过连接器根目录与忽略规则限定；持久化勾选规则留待后台同步方案。

网页改为连续单文件短请求，显示新增、更新、未变化与失败计数。请保持页面打开；
停止/离页不再提交后续文件，已发出的单文件请求可能完成，已保存的资料不会回滚。
服务端首批固定文件ID上界，后续按游标推进；失败项也推进游标，不在同一轮无限重试。
网络中断后先刷新清单再重试未成功项，不将“请求未收到响应”等同于“全部文件失败”。
扫描仍是持久后台任务，而本批下载不是离页持续执行的后台任务，不混淆两种进度。

单文件下载设置45秒总时限，检查响应大小声明并在流式读取时累计限制字节数，
不再等整个超大文件下载完才拒绝。Web入口仅为`sync-batch`设置65秒代理时限，
不改变其他API的超时；外层反向代理也需要覆盖这一时长。选择请求限制64 KiB，
后端最多接受1000个明确文件ID，每次最多下载一个文件。不同工作空间仍严格隔离。

“已入库/已同步”指原文件和版本已保存、解析任务已排队；正文提取、AI整理、切片与
向量是否完成须到处理中心或文档详情查看。WebDAV沿用来源下载限额，不随上传页的
动态限额自动放大；空文件和超过限额会明确失败，其他文件仍可继续。

新增管理员内部接口：`GET /api/webdav/{id}/browse`（目录/搜索/状态/分页）及
`POST /api/webdav/{id}/sync-batch`（显式文件或目录范围、单文件游标批次）。
不变更REST v1/MCP读取契约，不授予远端写入权限，不自动重试历史失败资料。

## 原版预览与版本一致性

WebDAV原件解析后可释放本地临时副本；正文、版本和派生结果仍然保留。因此无本地
blob不等于远端文件丢失。文档详情与引用预览带version_id时，优先使用该版本现存的
本地原件；无本地原件则按工作空间内的连接器回取，必须校验字节SHA-256与指定版本
一致才返回。远端已修改则409提示版本不一致，不能静默展示成旧证据。

该回取不持久保存原件、不新建版本或解析任务。不带version_id的既有“下载原文件”
入口仍按需读取远端当前文件；它与固定版本的引用预览有不同的新鲜度语义。

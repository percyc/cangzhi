# 藏知开发路线图

更新时间：2026-07-31

路线图按产品风险排序，不按功能数量排序。每个阶段都必须保持现有知识可读取、可导出、
可恢复；任何新能力不能破坏事实源和当前可用索引。

## 1. 已交付基线

### 基线 A：可靠沉淀

- 随手记、文件和网页链接采集
- PDF、DOC、DOCX、XLSX、XLS、Markdown、TXT 与 HTML 基础解析
- 原文、网页快照、哈希去重和文档版本
- 数据库后台任务、失败重试和处理状态
- 单用户登录、模型密钥加密和服务端真实鉴权

### 基线 B：自动组织

- 默认分类树和分类管理
- 确定性文档类型识别
- AI 摘要、主分类和标签
- 无模型降级与历史待整理资料自动补跑
- 标签管理、合并及 AI 合并建议

### 基线 C：检索与问答

- 结构优先父子切片和原文定位元数据
- Excel 工作表、数据区域、列名和行范围感知的二维切片
- PostgreSQL 全文索引
- 独立 Embedding 渠道和版本化向量档案
- 全库向量构建、失败重试、原子启用和回滚
- 全文与向量双路召回、元数据过滤和 RRF 融合
- 向量故障自动降级
- 带引用的搜索和知识问答
- 知识范围及会话式问答界面
- 快速问答与受控多步工具调用的深度分析双模式

### 基线 D：知识生命周期与数据主权

- 知识回收站、恢复、批量永久删除和 Blob 引用安全清理
- WebDAV 只读连接、编辑、停用、扫描、同步和删除影响选择
- WebDAV 远端缺失延迟确认、自动回收、自动恢复和本地快照保留
- 单篇及全库 Markdown/JSON 导出
- PostgreSQL 与 storage 联合备份、校验和隔离恢复演练

### 基线 E：知识中枢

- 统一 KnowledgeScope
- 稳定 REST v1 只读契约
- JSON CLI
- MCP Streamable HTTP 取证工具
- Hermes、OpenClaw 等平台可复用的 Skill 模板
- 独立个人访问令牌、权限、撤销和接入配置提示

## 2. 当前阶段：个人 Beta 质量闭环

目标：不是继续堆入口，而是让真实个人资料长期运行后仍然可靠、准确、容易维护。

### P0：可观察的处理质量

- 为文档列表和详情补齐统一的“采集、解析、理解、切片、全文、向量”状态。
- 区分等待、执行、成功、降级、失败和无需执行，避免一个“完成”掩盖阶段差异。
- 增加处理耗时、失败类型、模型调用和向量覆盖统计。
- 对大文档、异常格式、编码和网络失败建立可重复测试样本。

验收：用户能回答“哪些文档尚未解析或没有当前向量”，并能从页面发起正确的恢复动作。

### P0：检索质量评测

- 建立至少 30 个真实黄金问题，标注正确文档、片段和来源位置。
- 分别评测全文、向量和混合检索的 Top 5 命中率。
- 增加切片边界、上下文扩展和重复片段诊断。
- 只有在 RRF 明显不足且评测证明有效时，才引入 Reranker。

验收：混合检索不低于单路最佳结果；错误可定位到解析、切片、召回、融合或回答阶段。

### M4-1 结构化表格问答

- [x] 将 Excel 数据区域生成可重建的持久化行索引。
- [x] 支持安全的筛选、分组、计数、去重计数、求和、平均、最值和排序。
- [x] 将计算结果与语义检索统一返回为“工作表 + 行范围”引用。
- [x] 使用文档摘要、表名、列名和样例进行语义路由，口语关键词仅作弱信号。
- [x] 增加 Parquet/DuckDB 单数据集执行后端、筛选聚合下推、资源边界和原子版本切换；
- [ ] 增加多表关联、透视、复杂日期函数和跨数据集语义关系；
  普通个人规模继续使用轻量内置执行器。

### P0：采集与来源稳定性

- WebDAV 定时扫描、运行记录、失败重试和手动立即执行。
- 连接器级文件数量、待同步、缺失确认、回收和恢复统计。
- 批量导入的限流、断点续扫和增量处理。
- 网页抓取失败原因分类与可恢复策略。

验收：大量已有文件可以渐进导入，不阻塞日常使用；扫描失败不会触发远端缺失确认。

### P1：问答记录与审计

- [x] 把问答记录、知识范围和实际引用快照保存到服务端，而不是只在浏览器临时保留。
- [x] 每次提问独立检索，不把历史问答静默注入模型上下文。
- [x] 支持跨设备回看和删除记录，并明确提示“问答记录不是模型记忆”。
- [ ] 支持记录重命名、归档、搜索和按原范围重新运行。

验收：刷新或更换设备后仍可回看历史回答及当时证据；新问题的检索结果不受旧问答
污染。连续推理和长期记忆由外部 Agent 负责，藏知继续作为可追溯的知识中枢。

## 3. 下一阶段：快速采集与受控接入

### 快速采集

- 专用入库邮箱或 IMAP 轮询
- 浏览器扩展
- 手机分享入口或 PWA 快速记录
- RSS、稍后读和批量文件夹导入增强

所有新来源都必须先满足：原文可追溯、稳定外部身份、幂等、失败可重试、删除语义明确，
再接入 AI 理解与自动归类。

### 受控写入 API

- URL、随手记和文件采集的稳定 v1 接口
- `knowledge:write` 最小权限
- `Idempotency-Key` 与任务状态查询
- 写入审计、速率限制和大小限制

外部 Agent 默认仍然只读。写权限由用户主动创建和授权，不从现有读取权限自动升级。

## 4. 后续：领域理解与关系发现

- OCR 及扫描 PDF 质量增强
- 法律：编、章、节、条、款、项及引用关系
- 合同：主体、金额、期限、义务、违约和风险
- 论文：问题、方法、数据、结论、局限和参考文献
- 会议：决策、待办、责任人和截止时间
- 相似资料、重复观点和冲突提示
- 智能专题与选择性 GraphRAG

领域能力以处理 Profile 增量实现，不为每个行业复制一套知识库。

## 5. 暂不进入基础路线

- 多用户组织版和复杂协同权限
- 双向 WebDAV 文件同步
- 默认开放 Agent 管理或永久删除权限
- 用完整知识图谱替代全文与向量检索
- 自动改写或覆盖用户原文
- 在检索评测不达标时单纯扩大回答模型

## 6. 阶段控制规则

1. 新数据源先通过可靠保存和生命周期验收，再增加 AI 自动化。
2. 新模型或向量索引未完成兼容测试和全库构建前，不替换当前服务索引。
3. 不可逆操作必须由用户明确发起；后台任务只能执行可恢复动作。
4. 网页、API、CLI 和 MCP 不复制业务规则，统一复用服务层。
5. 每个阶段同时提交测试、迁移、运行文档和可观察状态。

# 藏知开发路线图

更新时间：2026-08-10

路线图按产品风险排序，不按功能数量排序。每个阶段都必须保持现有知识可读取、可导出、
可恢复；任何新能力不能破坏事实源和当前可用索引。

## 1. 已交付基线

### 基线 A：可靠沉淀

- 随手记、文件和网页链接采集
- PDF、DOC、DOCX、XLSX、XLS、Markdown、TXT 与 HTML 基础解析
- 原文、网页快照、哈希去重和文档版本
- 数据库后台任务、失败重试和处理状态
- 单用户登录、模型密钥加密和服务端真实鉴权

### 基线 B：自动组织

- 默认分类树和分类管理
- 确定性文档类型识别
- AI 摘要、主分类和标签
- 无模型降级与历史待整理资料自动补跑
- 标签管理、合并及 AI 合并建议

### 基线 C：检索与问答

- 结构优先父子切片和原文定位元数据
- Excel 工作表、数据区域、列名和行范围感知的二维切片
- PostgreSQL 全文索引
- 独立 Embedding 渠道和版本化向量档案
- 全库向量构建、失败重试、原子启用和回滚
- 全文与向量双路召回、元数据过滤和 RRF 融合
- 向量故障自动降级
- 带引用的搜索和知识问答
- 知识范围及会话式问答界面
- 快速问答与受控多步工具调用的深度分析双模式

### 基线 D：知识生命周期与数据主权

- 知识回收站、恢复、批量永久删除和 Blob 引用安全清理
- WebDAV 只读连接、编辑、停用、扫描、同步和删除影响选择
- WebDAV 远端缺失延迟确认、自动回收、自动恢复和本地快照保留
- 单篇及全库 Markdown/JSON 导出
- PostgreSQL 与 storage 联合备份、校验和隔离恢复演练

### 基线 E：知识中枢

- 统一 KnowledgeScope
- 稳定 REST v1 只读契约
- JSON CLI
- MCP Streamable HTTP 取证工具
- Hermes、OpenClaw 等平台可复用的 Skill 模板
- 独立个人访问令牌、权限、撤销和接入配置提示

### 基线 F：个人多工作空间

- 单管理员可创建、切换、重命名、归档和恢复工作空间
- 旧数据和未指定空间的调用自动归入默认空间
- 文档、分类、标签、知识范围、WebDAV 来源和问答记录按空间隔离
- REST、CLI、MCP 和 Skill 可显式选择空间
- 对话模型、向量配置、备份和系统运维继续全局共享

### 基线 G：结构化数据库来源

- PostgreSQL/MySQL 加密连接配置、连接测试和只读目录浏览
- 按工作空间选择表/视图并导入本地数据集快照
- 受控行数、单元格、连接和语句超时，不开放任意 SQL
- 重导入沿用文档版本，事务失败回滚，新产物提交后清理旧 Parquet
- 数据快照直接复用 DuckDB、API 与 MCP 数据集查询

## 2. 当前阶段：个人 Beta 质量闭环

目标：不是继续堆入口，而是让真实个人资料长期运行后仍然可靠、准确、容易维护。

数据库连接器下一阶段再增加：导入前筛选/列选择、后台进度与取消、主键/更新时间增量
同步、定时刷新、CA 证书校验，以及受控 SQL dump 解析。上述能力未完成前，超出 10 万
行的表应先在来源数据库建立只读视图；系统不会执行用户上传的 SQL 脚本。

### P0：可观察的处理质量

- [x] 文档列表、处理中心和详情使用统一的解析、理解、切片、全文、向量状态。
- [x] 当前向量覆盖核对切片内容哈希，并兼容大型数据集的抽样向量策略。
- [x] 可筛选缺失/失败向量并定向批量补建，不重复下载、解析和切片。
- 增加处理耗时、失败类型、模型调用和向量覆盖统计。
- 对大文档、异常格式、编码和网络失败建立可重复测试样本。

验收：用户能回答“哪些文档尚未解析或没有当前向量”，并能从页面发起正确的恢复动作。

### P0：外部视觉 OCR（基线 H 第二阶段）

- [x] 外部 OCR 是独立于对话和向量渠道的第三套配置（OCR 阶段 2）。
- [x] Worker 读 `ai_runtime_configs` 注入 `ExternalOcrProvider`；外部失败
  保留本地非空结果，整份文档不会因外部模型失败而失败。
- [x] 触发条件（`no_text` / `low_chars` / `low_confidence`）和单文档
  外发页数限制可配置；超限后剩余候选页回退到本地识别。
- [x] `Block.extra` 与 `metadata.pdf_extraction` 同时记录本地与外部
  来源、引擎、provider、模型与 bbox；旧字段继续兼容。
- [x] 设置页增加“图片文字识别”面板，可视化展示本地 vs 外部统计与触发
  原因；密钥与图片字节不写入日志。
- [ ] 基于 OCR 黄金集评测：本地 tesseract、外部多模态、二者组合的
  Top-K 命中率与失败模式。
- [ ] 把评估结果与文档详情摘要暴露在处理中心。

验收：扫描 PDF 在本地置信度不足时自动尝试外部模型；超过外发页数上限
后剩余页继续走本地识别；不引入密钥或图片字节到日志。

### P0：检索质量评测

- 建立至少 30 个真实黄金问题，标注正确文档、片段和来源位置。
- 分别评测全文、向量和混合检索的 Top 5 命中率。
- 增加切片边界、上下文扩展和重复片段诊断。
- 只有在 RRF 明显不足且评测证明有效时，才引入 Reranker。

验收：混合检索不低于单路最佳结果；错误可定位到解析、切片、召回、融合或回答阶段。

### M4-1 结构化表格问答

- [x] 将 Excel 数据区域生成可重建的持久化行索引。
- [x] 支持安全的筛选、分组、计数、去重计数、求和、平均、最值和排序。
- [x] 将计算结果与语义检索统一返回为“工作表 + 行范围”引用。
- [x] 使用文档摘要、表名、列名和样例进行语义路由，口语关键词仅作弱信号。
- [x] 增加 Parquet/DuckDB 单数据集执行后端、筛选聚合下推、资源边界和原子版本切换；
- [ ] 增加多表关联、透视、复杂日期函数和跨数据集语义关系；
  普通个人规模继续使用轻量内置执行器。

### P0：采集与来源稳定性

- WebDAV 定时扫描、运行记录、失败重试和手动立即执行。
- 连接器级文件数量、待同步、缺失确认、回收和恢复统计。
- 批量导入的限流、断点续扫和增量处理。
- 网页抓取失败原因分类与可恢复策略。

验收：大量已有文件可以渐进导入，不阻塞日常使用；扫描失败不会触发远端缺失确认。

### P1：问答记录与审计

- [x] 把问答记录、知识范围和实际引用快照保存到服务端，而不是只在浏览器临时保留。
- [x] 每次提问独立检索，不把历史问答静默注入模型上下文。
- [x] 支持跨设备回看和删除记录，并明确提示“问答记录不是模型记忆”。
- [ ] 支持记录重命名、归档、搜索和按原范围重新运行。

验收：刷新或更换设备后仍可回看历史回答及当时证据；新问题的检索结果不受旧问答
污染。连续推理和长期记忆由外部 Agent 负责，藏知继续作为可追溯的知识中枢。

### 基线 H：扫描 PDF 文字兜底

- [x] PDF 解析先取可复制文本，原生字符不足的页面在有栅格图像时按
      候选进入 OCR 通道，避免无差别全文 OCR。
- [x] 通过 `pypdfium2` 渲染候选页为 PNG，用 `tesseract -l <lang> --psm 6 tsv`
      抽取词级结果，按 `block/par/line` 聚合成段落，词级坐标转回 PDF 点坐标。
- [x] Worker 配置 (`PDF_OCR_*`) 集中管控开关、语言、DPI、阈值、最大候选页与超时。
- [x] 解析结果附带 `metadata.pdf_extraction` 摘要（原生文字页 / OCR 完成 / 失败 / 跳过），
      在 `processing_status.parsing.extraction` 和文档详情页可见，单页失败不阻塞整体解析。

图片语义理解、版面重建与图表/公式识别仍属后续阶段。

## 3. 下一阶段：快速采集与受控接入

### 快速采集

- 专用入库邮箱或 IMAP 轮询
- 浏览器扩展
- 手机分享入口或 PWA 快速记录
- RSS、稍后读和批量文件夹导入增强

所有新来源都必须先满足：原文可追溯、稳定外部身份、幂等、失败可重试、删除语义明确，
再接入 AI 理解与自动归类。

### 受控写入 API

- **已完成**：文件上传的稳定 v1 接口、`external_id` 幂等版本更新
- **已完成**：`documents:write` 最小权限与文档 Scope Key 单篇/批量管理
- 待完成：URL、随手记采集的稳定 v1 接口
- `Idempotency-Key` 与任务状态查询
- 写入审计、速率限制和大小限制

MCP/外部 Agent 默认仍然只读。REST 写权限由用户主动创建和授权，不从读取权限自动升级。

## 4. 后续：领域理解与关系发现

### v1.0 后的通用文档理解演进

以 `v1.0` 保留已验证基线，先修正文与表格结构，再建立文档地图、派生产物版本、
分层 AI 理解和受约束边界建议，最后扩展统一探索与纠正入口。
分批验收见 [文档理解计划](DOCUMENT_UNDERSTANDING_PLAN.md)，任务见 BACKLOG 的
CZ-Q06 / CZ-N01–N06。本路线不意味着立即全库 AI 重切，也不取消 ADR-004 的规则底座。

- 图片语义理解、版面重建与图表/公式识别（接续基线 H）
- 法律：编、章、节、条、款、项及引用关系
- 合同：主体、金额、期限、义务、违约和风险
- 论文：问题、方法、数据、结论、局限和参考文献
- 会议：决策、待办、责任人和截止时间
- 相似资料、重复观点和冲突提示
- 智能专题与选择性 GraphRAG

领域能力以处理 Profile 增量实现，不为每个行业复制一套知识库。

## 5. 暂不进入基础路线

- 多用户组织版和复杂协同权限
- 双向 WebDAV 文件同步
- 默认开放 Agent 管理或永久删除权限
- 用完整知识图谱替代全文与向量检索
- 自动改写或覆盖用户原文
- 在检索评测不达标时单纯扩大回答模型

## 6. 阶段控制规则

1. 新数据源先通过可靠保存和生命周期验收，再增加 AI 自动化。
2. 新模型或向量索引未完成兼容测试和全库构建前，不替换当前服务索引。
3. 不可逆操作必须由用户明确发起；后台任务只能执行可恢复动作。
4. 网页、API、CLI 和 MCP 不复制业务规则，统一复用服务层。
5. 每个阶段同时提交测试、迁移、运行文档和可观察状态。

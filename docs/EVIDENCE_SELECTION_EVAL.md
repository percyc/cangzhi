# 文档内证据选择：2026-09-19 本地对照

## 结论

保留主证据、增加至多一条独立定位的补充证据，本地30题的预期来源短语覆盖从
21/30提高到29/30，原有通过题未退步。不是模型回答准确率，也不是全库泛化结论。
不重建切片或向量，不增加模型调用。实现和运行状态以 PROJECT_STATUS 为准。

## 方法

- `scripts/retrieval-fixtures.json` 固定30个问题、期望文档和短语，覆盖7份资料、PDF/
  DOC/DOCX/Markdown、2个空间。法律题仅检验指定历史文档的内容，不判断现实法律适用。
- 第一批7题用于诊断，其余23题用于扩大检查；不是盲测或人工独立标注，主要是中文资料，
  尚不能关闭CZ-R01/02的代表性黄金集及分路Top5评测任务。
- 原文中逐一验证期望短语均存在。每题在同一只读会话、相同授权范围、相同全文/向量
  候选上比较；查询向量只生成一次。候选模块仅加载于诊断子进程，不替换正式服务。
- NFKC与去空白仅用于断言，不改原文；检查目标文档的主context加补充context是否涵盖
  全部期望短语。该检查不保证数字与主体关系、条件逻辑、矛盾消解或最终引用正确。
- 候选复用缓存，不应把脚本候选耗时误读为端到端性能提升。正式检索仍有原全文扫描成本。

## 下一步与使用

```bash
python3 scripts/check-evidence-selection.py --candidate
python3 scripts/check-evidence-selection.py --candidate --indices 3 6 19 22
```

脚本仅在维护者的本地资料库有效，缺少对应资料时标记label_valid=false；合成测试不依赖
这些生产ID。下一批需要扩展独立来源、英文、反例、长表格、无答案题并标注精确来源位置；
再分析遗漏是候选不足、补充选择还是窗口截断，不以无限扩大上下文掩盖问题。
正式发布后外部调用方需消费 `supporting_evidence`，旧客户端忽略该字段仍得到原主证据。
